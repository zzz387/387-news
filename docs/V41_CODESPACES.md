# 387 News v4.1: управление и закрытое чтение в Codespaces

## Открыть с телефона — без локальных программ

[Создать Codespace из ветки PR №7](https://codespaces.new/zzz387/387-news?ref=codex%2Feditorial-policy-v41&devcontainer_path=.devcontainer%2Fdevcontainer.json&machine=basicLinux32gb)

1. Войдите в GitHub как **zzz387**, откройте ссылку и нажмите **Create codespace**. Выбирайте минимальную 2-core машину в пределах включённой бесплатной квоты; не соглашайтесь на платное превышение. Codespace пока **не создан** агентом.
2. Дождитесь установки. В меню VS Code **Terminal → Run Task** выберите **387 News: открыть панель** (на телефоне также доступно через Command Palette → Tasks: Run Task). Если автоматический запуск панели остановился на правах, после исправления выберите **387 News: запустить закрытую панель**, затем «открыть панель».
3. Нажмите **Запустить испытание**. Помощник проверит owner, текущий SHA PR, настоящий `trial-route` без Secrets/Gemini и Required reviewers; только после этого создаст защищённый trial. Production имеет приоритет. Не нажимайте Start повторно при неизвестном результате dispatch: сначала проверьте Actions.
4. Откройте ссылку запуска: **Review deployments → 387-news-v41-trial → Approve and deploy**. Не используйте Bypass. Когда GitHub блокирует self-review, подтверждает другой уже разрешённый reviewer — это правило не ослабляется.
5. В панели нажимайте **Проверить состояние**, при незавершённой работе **Продолжить** с прежней датой, после завершения **Открыть номер → Читать номер**. Приватная HTTPS-страница доступна в браузере телефона под владельцем Codespace. Фактический URL появится только после создания Codespace; сейчас действующая ссылка на номер отсутствует.

Установка и открытие панели **не вызывают Gemini**. Новый цикл начинается только кнопкой Start, настоящее выполнение — только после GitHub environment approval. PR не сливается; production не публикуется.

## Доступ GitHub и права

Devcontainer запрашивает поддерживаемые Codespaces repository permissions `contents:read` и `actions:write` для одного репозитория. Подтвердите штатный запрос GitHub на доступ, если он появился при создании/изменении Codespace. Панель не запрашивает пароль, PAT или секреты в чате и не печатает их.

Панель проверяет `gh api user`, `user/codespaces/NAME` (владелец и репозиторий), CLI список переадресованных портов и фактическую visibility. На каждом HTTP-запросе проверка повторяется; API-ошибка/публичный порт закрывает выдачу данных. До назначения Private сначала проверяется личность владельца. Используются реальные API при работе в Codespace; локальные unit-тесты проверяют только контракт ответов.

**Не предполагается**, что обычный Codespaces token имеет administration или codespace scope. Если GitHub отказывает, используйте штатную авторизацию GitHub/Accounts в Codespaces и запрос разрешений Codespaces. Нельзя подменять/искать токен либо снимать защиту ради запуска. Если прав на environment нет, владелец открывает [Settings → Environments](https://github.com/zzz387/387-news/settings/environments), выбирает **387-news-v41-trial**, включает Required reviewers с zzz387 и разрешает PR-ветку согласно существующей branch policy. Другие environments и production Secrets не изменять. После этого повторный запуск помощника обязан перечитать protection_rules и подтвердить защиту API. При недоступности API проверка остаётся заблокированной.

Если workflow_dispatch вернёт 404/422, помощник не отправит Gemini-run: сначала должен успешно завершиться настоящий `trial-route`. Workflow уже существует в main, однако это само по себе не доказывает поддержку новых inputs конкретной PR-ветки. Автоматического переноса YAML или PR в main нет. При реальной ошибке сохранить её HTTP-код и run, затем отдельно согласовать минимальное изменение маршрутизации — не внедрять production автоматически.

## Изоляция и просмотр

* Python3.12, Git (из devcontainer image), gh (официальная feature), cryptography, Playwright/Chromium и зависимости устанавливаются postCreate. Постоянные production Secrets не нужны.
* Сервер слушает только `127.0.0.1:8765`. Используется штатный GitHub HTTPS forwarding **Private**, точный hostname данного Codespace, проверка Host/Origin/Sec-Fetch-Site. Произвольные `X-Forwarded-*` не дают доверенного origin. Сохраняется случайный 256-bit внутренний токен.
* CSRF-токен, проверка Origin, ограниченные POST-действия, отсутствие CORS, CSP, no-store/no-referrer/nosniff; HTTP access-log отключён. URL с токеном не пишется в postStart log. Веб-панель открывается через встроенную команду браузера VS Code.
* Отдельный RSA3072 ключ владельца создаётся **только внутри Codespace**, в `/workspaces/.387-news-owner-review/` вне репозитория (0700/0600). В Actions отправляется только публичная часть. Production DRAFT/Gemini ключей в viewer нет.
* Архив официального Actions Artifact проверяется по owner/event/branch/workflow/SHA/status, затем RSA-OAEP/AES-GCM метаданным. Только финальные HTML/MD, assets, screenshots и безопасный review.json читаются в RAM; закрытые досье не переносятся. Plaintext не извлекается на диск. Временный download содержит только ciphertext.
* Чтение: первая полоса, 12 полных статей, ресурсы и источники; отчёт по статьям и фактические gemini_usage из review.json. Для незавершённого run панель показывает GitHub status, но **не выдумывает** количество готовых статей/расход; детали безопасного pipeline-status находятся в защищённом run.
* Иллюстрации выдаются, только если существующий rights/source pipeline их допустил; панель не добавляет внешние изображения и не загружает трекеры. Ручная литературная оценка остаётся pending: автоматические gates не доказывают литературное качество.

## Восстановление и квота

**Остановка и возобновление того же Codespace:** откройте его на github.com/codespaces, Resume. `/workspaces` сохраняет ключ и session.json. PostStart поднимает панель с новым токеном; снова выполните задачу «открыть панель», затем «Открыть номер» — архив повторно дешифруется в RAM. Само возобновление не генерирует статьи. При rebuild `/workspaces` сохраняется, но данные вне него могут исчезнуть.

**Удаление и создание нового Codespace:** ключ не экспортируется. В панели раскройте восстановление, укажите ID прежнего **trial** run и прежнюю дату. Подтвердятся provenance и наличие job trial; затем «Перевыдать архив без Gemini» запускает защищённый `trial-inspect` с новым публичным ключом и отдельным Required-reviewer approval. В Actions используется прежний encrypted checkpoint, новый owner bundle шифруется на новый ключ. Если номер ещё не готов, используйте «Продолжить» с той же датой. Нельзя менять дату, обнулять счётчики или создавать новый цикл взамен незавершённого. Если официальный checkpoint уже истёк/утрачен, восстановление блокируется; успех не обещается. Ciphertext Artifacts хранятся существующие 7 дней.

**Исчерпание квоты/429/503:** сохранённый зашифрованный checkpoint и общий ledger остаются источником истины. После восстановления квоты кнопка «Продолжить» повторно проходит route и approval, сохраняет дату и успешно завершённые этапы. Лимиты24/run,220/UTC-день и >=6сек не меняются; приоритет текущего и ближайшего production сохраняется. Бесплатной квоты может не хватить на быстрое завершение trial. Автоматического ежедневного или бесконечного dispatch из Codespace нет.
