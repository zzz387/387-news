## Настройки и оставшиеся границы доступа

GitHub connector позволяет стандартный merge, но не предоставляет dispatch/Variables/Secrets/Pages settings mutation. В Codex CLI авторизация не подтверждена, api.github.com ограничен сетью. Эти ограничения не обходятся. После merge использовать единственный автоматически запущенный push-run main; не создавать конкурирующий экземпляр. Existing schedule работал до внедрения; activation/approval Variables дополнительно проверит production-preflight.

Если требуется действие владельца: Settings→Secrets and variables→Actions→Variables (обе существующие переменные=true), либо Settings→Pages→Source=GitHub Actions с сохранённым387.su/HTTPS. Обязательное действие указывается только по реальному API/preflight результату. Нельзя объявлять настройки изменёнными без подтверждения.

## Критерий завершения и откат

Успех rollout не равен готовому номеру. Только12/12 принятых статей, финальный аудит, проверенный HTML, успешный commit/Pages и подтверждённый публичный HTTPS допускают заявление о публикации v4.1. До этого используются реальные RETRY_PENDING/BLOCKED/WAITING_FOR_RELEASE_TIME, дата и ссылка run, фактический ledger.

При критической ошибке сначала остановить новые production через существующие Variables, дождаться mutex, сохранить Artifacts/ledger, затем стандартный revert технических изменений. Не force-reset, не удалять новые статьи/исторический архив и не терять41 checkpoint при возврате31 кода. Полная [инструкция эксплуатации](POLICY_V41_OPERATIONS.md).
