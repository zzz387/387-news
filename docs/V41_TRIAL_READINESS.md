## Исправления

- Для C больше не требуется разрешение автора на неохраняемые факты/идеи. Это **не** разрешение на текст, перевод, авторскую подборку или объяснения. A/B по-прежнему требуют лицензии/доказательства. Конкретный спор, конфиденциальность, ограничения извлечения/AI и документальное `unknown` блокируют соответствующее использование. Подтверждённые ограничения AI проверяются и по текущему профилю домена, чтобы старый checkpoint не мог их обойти.
- Самостоятельность C проверяется детерминированно и отдельным модельным решением по четырём направлениям: композиция, формулировки, примеры, объяснения. Неадресный отказ не назначает случайный раздел на переписывание. Лишь подтверждённый `affected_ids` допускает адресное исправление.
- DOM-извлечение поддерживает Article/NewsArticle JSON-LD, несколько авторов, обычные и вложенные списки, таблицы/подписи, прямой текст внутри div/section, Drupal, WordPress, Frontiers и музейную разметку. Полное чтение не заменяется JSON-LD description/abstract/RSS. Paywall, robots, challenge, неоднозначность и отсутствие полного текста остаются блокировками.
- Для проверяемых институциональных источников отсутствие автора/даты явно сохраняется как `metadata_gaps`, без выдуманного авторства/даты. Список `config/source-profiles.json` подтверждает происхождение, **не выдаёт лицензию**. Новости по-прежнему требуют дату публикации и проверенную дату события в существующем окне72часа. Другие неизвестные источники с неполными метаданными остаются на проверке. Исправлено распознавание www/поддоменов WHO/NIH и исключён двойной учёт www-алиасов как независимых издателей. Для практических инструкций независимая база обязательна.
- Короткие блоки объединяются в технические операции с сохранением всех id/offset. Анализ/перевод используют6тыс. символов входа одной операции, проверки —24тыс.; более длинный материал проходит несколько операций. Это ограничения запросов, **не объёма статьи**. Проверка требует покрытия каждого id. Общий контекст ограничен120тыс.; превышение блокирует операцию без обрезки.
- Завершённые части, проверки и анализ источника сохраняются. Анализ одного и того же оригинала переиспользуется между материалами/независимыми проверками только при совпадении URL, content hash, метаданных и версии аналитического контракта. Счётчики операций и реальных HTTP-резервирований по этапам сохраняются до HTTP, включая ошибки/прерывания. Общий ledger остаётся источником истины.

## Квота: измерения и прогноз

Реальное потребление Gemini этого задания: **0 HTTP-запросов**. Измерены только размеры/структура публичных исходников и число технических пакетов. Выходные тексты, число исправлений, задержки и реальные ошибки модели пока неизвестны. `model_usage` и `quota41.actual_usage()` дадут фактические данные испытания отдельно по анализу, подготовке, фактчекингу, полноте, литературе и аудиту.

Формулы без повторов: A = S+3R+P+I; B = S+T+3R+P+I; C = S+1+K+3R+1+I. Здесь S — пакеты анализа, T — пакеты перевода, R — пакеты полного подготовленного текста/инструкций для **каждой** из трёх независимых проверок, K — разделы собственного плана, P — извлечение практического манифеста A/B, I — дополнительные независимые анализы. Для C последние+1 — отдельная проверка самостоятельности. Итоговый аудит номера ещё минимум1 запрос. Суммируются **фактические HTTP**, а не только логические операции; невалидный JSON/429/503 также расходуют резервирования.

Примеры `quota41.estimate` / `issue_scenario` (это сценарии, не нормы объёма/числа разделов):

| Сценарий C | На статью | 12 статей+аудит+независимая база | С2 резервами и20% запасом |
|---|---:|---:|---:|
| S=2,R=1,K=4 | 11 | 139 при6 дополнительных общих операциях | 194 |
| S=2,R=3,K=4 | 17 | 211 при6 дополнительных общих операциях | 294 |

Следовательно,220/сутки может хватить для умеренного сценария, но **стабильность12 статей ещё не доказана**. Большие исходники/тексты,21 подробная инструкция, число резервов и исправления могут превысить220. Для B S=3,R=1 даёт9 операций до дополнительных источников/манифеста; R=3 даёт15. Перед испытанием нельзя заменить эти оценки выдуманными живыми замерами. Отдельные проверочные ссылки WHO (движение детей до5лет) и NIH (здоровье взрослых) добавлены в набор; Harvard оставлен отрицательным контролем неоднозначной структуры; их доступность фиксируется новым source smoke. Модель обязана подтвердить релевантность и независимость конкретных фактов, два домена сами по себе не дают одобрения.

Уже реализованные оптимизации сохраняют качество: пакетирование полного входа, раздельные три проверки полного текста, переиспользование привязанного к hash анализа, отсутствие повторов завершённых операций. Дальнейшие варианты при недостатке220: заранее готовить законные evergreen-резервы в свободные квотные окна, выбирать равноценные полные источники с ясной фактологией/правами, использовать только действительно новые независимые доказательства, планировать работу по прогнозу оставшихся операций. Если нагрузка всё равно превышает220, блокировать выпуск/дождаться квоты и сообщать о нехватке; не укорачивать статьи, не объединять проверки в одну и не повышать лимиты. Платный API не подключён.

## Безопасное испытание после отдельного разрешения

Механизм добавлен в **существующий** `daily-v31.yml`: `phase=trial` / `trial-inspect`. Новый workflow в main или слияние PR для подготовки не нужны. Запуск возможен только dispatch владельца, на ветке `codex/editorial-policy-v41`, с точным одобренным SHA, `preview=true` и явной фразой разрешения. Jobs push/PR не получают Gemini/ключи. Production prepare/deploy не запускаются для trial-фаз.

1. После отдельного разрешения владельца проверить текущий PR/CI и SHA. В Settings→Environments владелец создаёт `387-news-v41-trial` и включает **Required reviewers**. При необходимости добавить себя (без запрета самоодобрения) либо другого проверяющего. Новые Secrets/production Variables не нужны. Интеграция не изменяет эти настройки. Если тариф/права не позволяют включить защиту, не покупать ресурсы и не обходить её: испытание останется заблокированным.
2. Прочитать список источников/отрицательные контроли. Source smoke должен подтвердить достаточный пул. Будущие внешние ошибки означают замену источника либо блокировку, а не право додумать текст.
3. На машине владельца с уже авторизованным GitHub CLI получить публичный SHA и запустить существующий workflow на PR-ветке. Указать новую будущую дату (например,2026-10-28, если ещё подходит):

```sh
trial_sha="$(gh pr view 7 --repo zzz387/387-news --json headRefOid --jq .headRefOid)"
gh workflow run daily-v31.yml --repo zzz387/387-news \
  --ref codex/editorial-policy-v41 \
  -f phase=trial -f preview=true -f target_date=2026-10-28 \
  -f trial_approved_sha="$trial_sha" \
  -f trial_confirmation=RUN_V41_TRIAL_WITH_GEMINI
```

Это **инструкция будущего запуска**, а не разрешение, выданное этим PR. Если GitHub не принимает branch inputs, сохранить ошибку и сообщить владельцу; не сливать PR ради обхода. Старый web UI может показывать только inputs main; CLI использует существующий workflow с указанным ref.

4. Одобрить environment job. Он проверяет владельца, SHA и наличие required reviewers. Лишь после этого trial-job получает общий с production lock `387-news-stage-v31`, восстанавливает официальный зашифрованный checkpoint и **тот же** дневной ledger. Во время ожидания environment review production не блокируется. Не запускать испытание в окно утренней публикации.
5. Выполняется только preview в отдельном временном дереве. Лимиты24/220, интервал6секунд и сохранение прогресса прежние. Повторять `trial` с **той же датой** после остановки/квоты; при изменении кода снова одобрить точный новый SHA. Старый trial может продолжаться после смены суток, если его официальный artifact сохранился. Новую прошлую дату без checkpoint запускать нельзя.
6. Перед упаковкой оригиналы повторно проверяются; изменившийся/недоступный кандидат сохраняется, но выводится из ready и заменяется резервом при следующем продолжении. Остальные статьи/проверки не перегенерируются. Успех — `trial_complete=true`:12 статей с полным HTML/Markdown, обязательными рубриками, итоговым аудитом, UNICEF21 в режиме C и лицензированным B. До этого зелёный workflow означает только сохранённое продолжение. Если для фактов/прав/состава не хватает доказательств, выпуск остаётся незавершённым.
7. Chromium проверяет все12 страниц при320,390,1440px (в CI — также длинный синтетический текст и неразрывный заголовок): отсутствие горизонтального переполнения/обрезанного или скрытого основного текста, один источник, сохраняет верх/низ страниц. Это browser smoke, не субъективная оценка дизайна/литературного качества.
8. `trial-review.enc` содержит HTML/Markdown,72 скриншота и результаты проверок; AES-256-GCM с отдельным AAD, ключ только существующего GitHub Secret. Срок хранения7дней. Trial-checkpoint тоже7дней, общий ledger90дней. В публичном репозитории plain Actions Artifacts не считаются приватными, поэтому **незашифрованного ZIP/HTML/скриншотов не загружается**. Просмотр/восстановление закрытого пакета выполняется внутри защищённых Actions, ключ не экспортируется.
9. Для повторной сборки/проверки завершённого сохранённого trial без Gemini использовать `phase=trial-inspect` с теми же датой/SHA/preview. Она читает официальный checkpoint, проверяет12 шлюзов и пересобирает зашифрованный обзорный пакет; генерацию не вызывает.
