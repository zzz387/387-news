# Техническое задание Codex: применить редакционную политику 4.2

**Основной документ:** `docs/editorial-policy-v4.2.md`. **Сначала** проверь настоящее состояние последнего production checkpoint через штатный защищённый `inspect` / Actions logs. Не выводи содержание закрытого досье, Secrets и исходных текстов в публичный git/log. Публичных слов «10 фрагментов, 0 статей» недостаточно для точной статистики по кодам отказов; сравни реальные метрики с анализом кода.

## Обязательные изменения без потери архива

1. **Состав:** `min_articles=8`, `target_articles=12` (ориентир, не hard cap), допускается 13+ при наличии готовых качественных текстов. Изменить `policy41`, `config/editorial.json`, `editorial41.select_ready/validate_issue/approve_selection/advance`, `publication41.build/validate_local_release`, `pipeline.report`, `site_checks`, численные проверки и шаблоны. Никаких жёстких `len == 12` для новых выпусков. Особый закреплённый переиздаваемый выпуск с отдельным контрактом и исторический архив не менять.
2. **Дедлайн:** как только к 06:00 МСК есть 8+ полностью допущенных статей, собирай номер без ожидания очерков, обязательного набора рубрик или резервов. До 06:00 можно добирать дополнительные материалы без ущерба принятой восьмёрке. Если <8, сохраняй прогресс, сообщай и продолжай; не публикуй фейки.
3. **Тематический охват:** все утверждённые направления сохраняются, но три рубрики и 2–3 очерка становятся soft-priorities. Финальный аудит не должен блокировать только из-за баланса/глубины.
4. **Глубина C:** в `editorial41.prepare` и `review` `record.requirements` — идеи для отбора, не `set(requirements)<=covered`. Проверяй только требования выбранного плана/заголовка. Разреши короткую самостоятельную статью и честное сужение темы. Для A/B сохраняй полное содержание.
5. **Названия практических материалов:** в `content41.semantic_structure` для C не наследовать количество занятий из `source.title`, если оно не обещано в собственном `article.title` и контракте специального номера. По желанию пользовательской редакции можно добровольно подготовить 21; если заявлено 8 — обязательны 8. Сохранить самостоятельность и инструкции.
6. **Блоки/повторы:** `ARTICLE_BLOCK_INVALID` и `REPEATED_CONTENT` сначала проходят безопасную локальную нормализацию допустимых форматов и удаление *буквального* дубля при отсутствии потери фактов. Не объединяй разные занятия с похожими глаголами. Исправление форматирования не должно снимать фактические approvals; смысловые изменения должны их инвалидировать.
7. **Повторные проверки:** классы hard/repairable/soft. Hard: права, безопасность, критический факт, отсутствие текста/источника, A/B полнота, действительно ложное обещание заголовка. Repairable: блоки, буквальные повторы, оформление. Soft: длина, глубина, стилистика, равномерность рубрик. Не называй soft-проблему новым hard-кодом.
8. **Промпты:** адаптируй `editorial41` так, чтобы Gemini мог честно выбрать ограниченную тему C, вернуть короткую законченною статью и не застревал в принудительном покрытии всех extracted requirements; критикуй ровно существующие ошибки, не требуй весь исходник в каждом разделе.
9. **Миграция:** не удалять старые `version=41` checkpoints и `ledger`; принятые parts/готовые статьи/данные прав сохраняются, инвалидация approvals только при изменённых фактах/правах/контрактах. Исторические публикации не перегенерировать. Повторные запуски идемпотентны.
10. **Дата:** дневной выпуск — 06:00 МСК; если уже поздно, без новых дат/перезаписи архива завершай предназначенный номер согласно release-queue. Ограничение `24/run, 220/day` и cooldown/Secrets/Pages источник не менять без отдельного согласия.

## Проверки приёмки

- Успешный номер при **8, 9, 11, 12 и 13** ready; 7 не проходит.
- Нет hard-block при отсутствии одной приоритетной рубрики и полном отсутствии очерков; настоящие дубли/опасные советы остаются блокерами.
- 10 сохранённых sections при 0 ready не представляются как готовые статьи; понятный отчёт по статусам и кодам.
- C по UNICEF с собственным честным заголовком «8 игр»: 8 применимых инструкций проходит; собственное «21 игра» с 8 — блокируется. A/B всегда полностью.
- Ошибочный block kind автонормализуется без потери смысла, буквальный повтор блока убирается без двойного копирования, разные игры с общими фразами сохраняются.
- При восьми допущенных до дедлайна номер выходит без 9–12 и резервов. Ни одна готовая статья не стирается при cooldown, rate-limit, перезапуске или неудаче другого кандидата.
- Тесты GitHub Actions проходят; CI синтетика не равна реальному выпуску, а live-run не запускается без штатного разрешения.

**Порядок внедрения:** PR на код, тесты и обратная совместимость, затем после проверки — отдельное решение владельца о слиянии и производственном запуске. Обновление только документа не меняет текущий production-конвейер.
