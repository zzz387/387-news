На текущем рабочем окружении:

- Managed egress ограничен package-manager hosts; `api.github.com` не разрешён. Доступ через proxy не обходился и конфигурация сети не менялась.
- Подключённая GitHub-интеграция разрешает изменения кода PR, но не предоставляет environment mutation / workflow dispatch. GET `repos/zzz387/387-news/environments/387-news-v41-trial` отклонён самой интеграцией: `INVALID_ARGUMENT`, HTTP400, `GitHub Fetch URL is not an allowed public GitHub repository or search endpoint`. Это **не** доказательство отсутствия environment в GitHub.

Поэтому статус `387-news-v41-trial` и Required reviewers **не подтверждён**, реальные branch inputs/ref пока не испытаны dispatch-запросом, trial URL отсутствует. Обход через push, фальсификацию GITHUB_EVENT_NAME, подмену actor или отключение защиты не использован. API-ключи в чат не требуются.

## Что теперь автоматизировано для авторизованного владельца

`scripts/trial_control41.py` использует обычный уже авторизованный owner `gh` на ПК:

1. Проверяет аккаунт `zzz387`, открытый PR№7, ветку и свежий40-значный SHA.
2. Выбирает завтра по Europe/Moscow только при первом старте. `resume`/`inspect` берут прежнюю дату из локальной сессии; повторный `start` не создаёт ещё один цикл. Если предыдущий run ещё выполняется/ждёт одобрения, повторный dispatch не создаётся.
3. Читает workflow именно из проверенного SHA и отправляет **настоящий** `phase=trial-route` на PR-ветку через официальный API. Этот job не имеет Secrets, не проверяет/обходит environment, не обращается к Gemini. Помощник требует успешный `trial-route` и skipped production jobs; одного синтаксического YAML недостаточно.
4. Только после подтверждённой маршрутизации читает/создаёт **ровно** `387-news-v41-trial`, добавляет владельца в Required reviewers и перечитывает protection_rules. Существующих reviewers, wait_timer и запрет self-review не удаляет. Ограничение protected branches не снимает. Никаких approval/bypass API не вызывает.
5. Создаёт `phase=trial` с текущим SHA, preview=true, правильной датой и явной trial-confirmation. Создаёт локальную сессию с датой/SHA/run id, без API Secrets. Выводит ссылку на настоящий run и необходимый Review deployments.
6. Не подтверждает GitHub gate за владельца. При недостаточных правах/неподдерживаемых branch inputs останавливается до Gemini; main не меняет.

Если actual branch dispatch отвергнут GitHub, это будет новый фактический блокер. Разрешение на изменение main ради маршрутизации не предоставлено; помощник не делает такого изменения.

## Приоритет production и квота

Новые проверки выполняются **внутри защищённого job**, перед первой модельной операцией:

- сегодняшний production-выпуск должен существовать в репозитории и подтверждаться по HTTPS;
- официальный encrypted checkpoint ближайшего следующего production-выпуска должен быть восстановлен в отдельный путь, иметь main/preview=false, правильную дату, audit_passed и полный принятый состав по своей исторической схеме;
- после production должно оставаться минимум24 из220 резервирований текущих суток UTC для отдельного trial-run. Иначе `trial_deferred` содержит конкретный код, запросов Gemini —0;
- admission не меняет ledger, не увеличивает лимиты и не переписывает production checkpoint. Используется тот же mutex `387-news-stage-v31`; ожидание environment-review этот mutex не занимает;
- `trial-inspect` не генерирует текст и не расходует Gemini. Публичный архив берётся из отдельного свежего readonly checkout main, а не из устаревающих файлов PR-ветки; он используется только для admission/поиска дублей. Успешное сохранение checkpoint/deferred-run не означает `trial_complete=true`.

Последний прочитанный production-run [40290319907](https://github.com/zzz387/387-news/actions/runs/40290319907) от26.10.2026 11:09МСК сообщает `PUBLISHED`,8 статей за26октября, `requests_used_today=0`;207 запросов относятся к quota_day25октября. Это исторический публичный status, не разрешение зарезервировать сегодняшние220: перед trial нужны свежий ledger и подтверждение готовности следующего production-выпуска внутри защищённого job.

Это консервативный приоритет обычной газеты. Если у production нет свободной квоты, trial откладывается; разрешение на испытание не является разрешением вытеснять основной выпуск. Факт дефицита надо сообщать, не снижать качество и не сбрасывать счётчики. Повторные запуски сохраняют принятые части и проверки.

## Как устроен закрытый просмотр без production-ключа

Существующий `trial-review.enc` сохраняется с прежним DRAFT_ENCRYPTION_KEY только для восстановления внутри Actions. Дополнительно создаётся **owner-review.enc**:

- отдельный RSA3072 private key генерируется **на ПК владельца**, хранится вне git с0600 на POSIX в `~/.local/share/387-news-owner-review/`; на Windows требуется закрытый пользовательский профиль, не общая папка;
- в workflow input поступает **только публичный SPKI**, он не секрет и не является API-ключом;
- в Actions генерируется новый случайный AES256 key, ZIP шифруется AES-GCM, этот ключ шифруется RSA-OAEP-SHA256 на публичный ключ владельца; дата/SHA/fingerprint аутентифицированы;
- ни production DRAFT key, ни Gemini key не попадают в owner bundle, локальный viewer, JavaScript или сторонний сервис;
- `owner-review.enc` с HTML/Markdown/иллюстрациями/скриншотами и читательским редакционным протоколом хранится encrypted artifact7дней. Исходные досье, prompts и закрытые проверочные цитаты в owner-пакет не входят;
- viewer проверяет официальный run (владелец, workflow_dispatch, ветка, SHA, success), скачивает **зашифрованный** artifact через owner `gh`, расшифровывает в RAM и отдаёт только на127.0.0.1 со случайным URL-токеном. Не извлекает plaintext ZIP/HTML на диск, не показывает ключи, не пишет URL в HTTP access log;
- запросы без токена, с чужим Host/Origin, path traversal, досье/служебные файлы отклоняются. CSP, no-store и no-referrer защищают локальное чтение. Закрытый протокол и все12 статей доступны из панели в верхней части страниц. Ручная литературная оценка явно остаётся pending.

Это практически проверенный **вариант для ПК**, без дополнительного хостинга/платных ресурсов. `localhost` ПК **не доступен с телефона**. В существующем публичном GitHub нет предоставленного owner-only веб-хостинга готового номера; Pages/Gist/plain Artifacts для этого непригодны. Приватный облачный preview/туннель не создавался. Адаптивность320/390px проверена Chromium, но это не утверждение о сетевом доступе с физического телефона. Для телефона нужна отдельно подтверждённая закрытая инфраструктура; ради удобства материалы не делаются общедоступными.

## Одно необходимое действие владельца до GitHub Approve

На **своём ПК с уже авторизованным owner gh**, в checkout PR№7:

```sh
python -m pip install 'cryptography>=44,<49' tzdata
python -m scripts.trial_control41 start
```

Если репозитория ещё нет: `gh repo clone zzz387/387-news`, перейти в `387-news`, затем `gh pr checkout 7`. Помощник автоматически выполняет доступные API-настройки/route probe/dispatch; пароль или токен в чат не передавать. При403 на environment необходимые минимальные UI-действия: [Settings→Environments](https://github.com/zzz387/387-news/settings/environments) → `387-news-v41-trial` → Required reviewers → `zzz387` → Save protection rules. Другие environments не менять.

После создания run: открыть выведенную ссылку → **Review deployments → 387-news-v41-trial → Approve and deploy**. Если self-review запрещён существующим правилом, подтверждает другой настроенный reviewer. **Bypass не использовать**. Сейчас конкретной ссылки на ожидание нет, потому что dispatch технически не выполнен.

После завершения run:

```sh
python -m scripts.trial_control41 resume   # продолжение того же номера после квоты/остановки
python -m scripts.trial_control41 inspect  # повторная сборка/упаковка без Gemini
python -m scripts.trial_control41 open     # готовый номер открывается в браузере этого ПК
```

`resume` и `inspect` снова проходят обязательное GitHub-подтверждение. `open` отказывается считать deferred/checkpoint-only run готовым, если owner artifact отсутствует. Ключ владельца не удалять; при утрате создать новый локальный ключ и выполнить защищённую re-export проверку через inspect, не экспортировать production key. Если approval первого старта задержался до потери будущей даты и checkpoint ещё нет, API-run блокируется; нельзя автоматически менять дату уже начатого номера или слепо дублировать dispatch после сетевой неопределённости.
