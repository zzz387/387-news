## Конфигурация и состояния

`config/editorial.json` — единственная конфигурация v4.1: 12 статей, три обязательные рубрики, все 20 приоритетов, рекомендательные очерки, резерв, возраст новостей, часовой пояс и время выпуска. Число очерков и баланс не блокируются механической квотой. Темы образования, психологии, книг и кино допускаются вне приоритетного списка.

Технические ограничения размера HTTP-ответа, контекста/ответа одной операции и числа попыток не устанавливают редакционный объём. При превышении транспорта/контекста материал не обрезается: сохраняется `needs_review`/отклонение с кодом. Полные источники и переводы проходят последовательные операции с устойчивыми id/offset/hash; принятые части сохраняются. Независимый текст создаётся по собственному плану разделов. Ошибки JSON/незаконченные ответы вызывают ограниченные попытки; диагностируемый отказ проверки самостоятельного раздела — до двух исправлений этого раздела, затем замена кандидата. Все литературные и содержательные шлюзы повторяются для изменённого текста.

Кандидат: `discovered → preparing → ready`; отказ — `rejected`, неопределённые права/данные — `needs_review`, транспорт — `retryable_error` (до трёх попыток). `ready` означает успешные `source_verified`, `content_prepared`, `fact_checked`, `completeness_checked`, `editorial_checked`, `ready_to_publish`. Изменение содержимого, прав или метаданных делает связанные решения недействительными. После обновления документальных прав соответствующие кандидаты автоматически пересматриваются. Полностью отклонённый кандидат заменяется готовым резервом; принятые статьи не переписываются ради формального объёма.

Номер использует прежние статусы контроллера: исследование/написание/аудит, `APPROVED`, `WAITING_FOR_RELEASE_TIME`, `PUBLISHING`, `PUBLISHED`, `RETRY_PENDING`, `BLOCKED`. Общий отказ композиции без адресного решения сохраняет все статьи и блокирует повтор одинакового аудита. Адресный отказ заменяет только явно указанные `repair_ids` внутри затронутых `article_ids`. Не более четырёх вариантов финального аудита; одинаковый отклонённый вариант повторно не отправляется. Сброс этих ограничений автоматически не выполняется.

В публичном журнале только этап, безопасный код/статус и номера затронутых статей. Полные замечания, исходники, цитаты, проверочные ссылки и история исправлений остаются в зашифрованном checkpoint. Для диагностики использовать `inspect` штатного workflow, не скачивание содержимого. Существующий монитор открывает/обновляет GitHub Issue о блокировке выпуска без черновиков и Secrets.

## Документальное подтверждение прав

Доступность URL и ответ ИИ не дают права копировать/переводить произведение: права A/B по умолчанию неизвестны. Самостоятельный C может использовать неохраняемые факты без разрешения автора, но не его формулировки, композицию, подборку и объяснения. Конкретный спор или ограничения обработки блокируют C до проверки. Поддерживаются явно заявленные исходником CC BY 3.0 / CC BY 4.0 / CC0 с авторством и полной проверенной статьёй; остальные основания подтверждает человек. Автоматическая проверка распознаёт только этот узкий набор лицензий; прочие случаи передаются на проверку.

Ручное подтверждение прав A/B или разрешение обоснованного сомнения — проверяемое изменение `config/rights.json` через PR владельца. В публичный файл разрешено помещать только публичную ссылку/лицензию/доказательство и технический hash. Закрытое соглашение, dossier, переписку или персональный контекст туда не помещать. Если разрешение нельзя подтвердить публичным доказательством этим механизмом, кандидат остаётся заблокированным; экспортировать закрытые сведения запрещено.

Формат записи текста (заменить все примеры действительными публичными данными):

```json
{
  "url": "https://example.org/story",
  "content_hash": "SHA256 полного структурированного исходника из защищённой проверки",
  "uses": {
    "INDEPENDENT_ARTICLE": {
      "status": "allowed",
      "verification": "human_documented",
      "evidence_url": "https://example.org/public-permission",
      "basis": "Проверенное правовое основание именно этого использования",
      "checked_by": "Публичное имя/роль проверяющего",
      "checked_at": "2026-10-26",
      "conditions": [],
      "attribution": {}
    }
  }
}
```

Запись добавляется в `grants`; отдельно задать `ORIGINAL_REPUBLICATION`/`FULL_TRANSLATION`, если разрешены именно эти действия. `forbidden` не переопределяется открытой лицензией автоматически. `unknown` блокирует этот режим. Для A нужен русский исходник; для B — иностранный. Условия `attribution`, `license_notice`, `indicate_translation`, `no_modifications` исполняются; неизвестное условие блокирует публикацию. C требует собственного изложения, композиции и подбора примеров; права на независимое использование фактов не дают права скрытого перевода.

Изображения проверяются отдельно через `images`: точный `url`, `sha256` байтов, такие же документальные поля и атрибуция строкой. Разрешённый файл должен быть отдельно подготовлен как `assets/...`, проверяется hash и отсутствие symlink. Автоматической загрузки чужих фотографий нет; отсутствие иллюстрации допустимо. Лицензия текста не распространяется на фото автоматически.

`config/candidates.json` (необязательный публичный технический список): `{"candidates":[{"url":"https://example.org/article","verification_urls":["https://www.who.int/example"]}]}`. Только публичные ссылки, без текстов досье. RSS служит обнаружению URL, затем читается полный оригинал. Robots, paywall, неполное извлечение, пагинация и неоднозначный контейнер блокируют обработку; обхода нет. Извлечение требует проверенного происхождения и языка. Для институциональных неоперативных материалов отсутствие автора/даты явно фиксируется; для новостей дата публикации и подтверждённая дата события обязательны. Неизвестная/неполная разметка отправляется на проверку, а не заменяется аннотацией.

Для медицинских/опасных утверждений требуется независимый дополнительный источник и компетентный первоисточник. Ссылки из `verification_urls` читаются полностью; анализ сохраняет проверяемые буквальные цитаты каждой части. Они доступны фактчекеру и никогда не попадают в HTML. Наличие источников само по себе не гарантирует одобрения: нерешённый существенный вопрос блокирует публикацию. Без достаточной независимой базы используется резерв, а не выдуманное подтверждение.

## Миграция и публикация после отдельного разрешения

1. Владелец отдельно разрешает rollout, проверяет PR и подтверждения прав. Убедиться, что Pages Source = **GitHub Actions**, а не публикация всей ветки из корня. Интеграция не обходит отсутствие доступа к этой настройке.
2. После разрешённого слияния сначала использовать `workflow_dispatch`, `phase=run`, `preview=true`, новую дату. Незавершённый v31 checkpoint становится схемой 41; старая копия остаётся внутри `legacy_v31`, approvals старой политики не переносятся. Исходные тексты не уничтожаются, но прежний материал нельзя автоматически признать полным оригиналом/законным режимом. Повторное исследование и проверка могут потребовать квоту. Счётчики ledger и `_quota_snapshot` сохраняются; UTC-день, cooldown 429/503, лимиты24/220 и общий concurrency не меняются.
3. `check`/`inspect` читают существующий формат без генерации. Штатный `restore_ready.py` понимает v41; старое одобрение не может продвинуть новый непроверенный выпуск. Реальные закрытые данные не переносятся в локальное окружение или публичный git.
4. Для автоматизации нужны существующие Secrets `GEMINI_API_KEY`, `DRAFT_ENCRYPTION_KEY`, Variables `NEWS_AUTOMATION_V31_ENABLED=true`, `NEWS_RELEASE_APPROVED=true`. **Новые Secrets/env обязательными не стали.** Существующие значения в этой работе не изменялись; они могут быть уже включены на main. Поэтому слияние само может запустить подготовку/публикацию и требует отдельного разрешения.
5. Убедиться в12/12, успешных отдельных шлюзах, финальном аудите и приватной HTML-сборке. После разрешения production `run`, `preview=false`, дата выпуска. Контроллер не публикует до06:00; поздний запуск продолжает сохранённую работу. Перед выпуском повторно читаются оригиналы; изменение/недоступность блокирует выпуск. Рендер не публикует досье, полные проверки или `issue.json` новых номеров. Финальный Git commit объединяет страницы, главную, архив и sitemap; Pages переключает готовый пакет атомарно. Повторный запуск сохраняет байты уже опубликованного номера.
6. Проверить `python scripts/site_checks.py --expected-date YYYY-MM-DD --attempts 5` (только публичный HTTPS) и статус `PUBLISHED`. Успех preview и зелёный workflow не означают публикацию.

Расписание сохранено: подготовка во второй половине дня и ночью, пробуждение05:54 с ожиданием06:00, утренние окна восстановления. Размер и сложность исходников могут исчерпать бесплатную квоту; система сохраняет прогресс и блокирует неполный выпуск, а не снижает требования. Нельзя гарантировать 12 подтверждённых материалов ежедневно без достаточного пула легальных источников и независимых доказательств.

## Откат и ограничения

До rollout откат — закрыть PR; main и сайт не менялись. После rollout сначала остановить новые production-запуски переменной `NEWS_AUTOMATION_V31_ENABLED=false` (владелец), дождаться текущего concurrency, затем revert конкретных технических коммитов. Архивы не удалять и не переписывать. Версия31 не умеет продолжать41 checkpoint: сохранить официальный artifact и восстановить последнюю совместимую версию кода либо прежний v31 artifact внутри Actions. Не сбрасывать общий ledger. Для повторного включения нужны проверка preview и разрешение владельца.

Реальные Gemini/закрытые checkpoints и production не проверялись этой реализацией: выполнены моки и синтетическая сборка. Семантический фактчекинг/оригинальность остаются задачами модели с детерминированными блокировками; юридическое решение вне распознаваемой лицензии требует человека. Сложные JS/paywall/многостраничные источники, неизвестные условия лицензии и контекст, который нельзя безопасно обработать текущей операцией, остаются `needs_review`, без обхода и скрытого сокращения. Browser smoke добавлен для320/390/1440px: текущий результат смотрите в CI PR. Он использует синтетический номер; реальные статьи/иллюстрации проверяются только после отдельного разрешения на trial. Субъективную оценку дизайна автоматический smoke не заменяет.
