# Production: редакционная политика 4.1

Владелец **26 октября 2026 разрешил непосредственное внедрение PR №7 и ежедневную production-публикацию без предварительного trial**. Это заменяет прежние ограничения на rollout и обязательное испытание. CI, Required reviewers/branch protection GitHub там, где они действуют, права источников и все редакционные проверки сохраняются. Codespaces/trial не нужны production; экспериментальный код оставлен неактивным.

## Ежедневный конвейер

Единственный исполнитель — `.github/workflows/daily-v31.yml`, ветка `main`. Совместимые имена Variables `NEWS_AUTOMATION_V31_ENABLED=true`, `NEWS_RELEASE_APPROVED=true` и существующих Secrets `GEMINI_API_KEY`, `DRAFT_ENCRYPTION_KEY` сохраняются. Новых обязательных Secrets/Variables нет. Значения ключей не выводятся, не копируются, не заменяются.

`config/editorial.json` задаёт12 статей,20 тематических приоритетов, обязательные «Семья», «Москва и путешествия», «Здоровье и движение», рекомендательные2–3 очерка и06:00 Europe/Moscow. Норм длины нет. Неполный/непроверенный номер не публикуется. Полный оригинал→документальные права→A/B/C→отдельные факты/полнота/литература/самостоятельность→финальный аудит→HTML/MD→Chromium на320/390/768/1440→Git commit→официальный Pages deployment→HTTPS-проверка.

Существующие18 cron-окон сохранены: подготовка днём/ночью, пробуждение05:54 с ожиданием06:00 и утренние восстановления. GitHub cron/Pages могут задерживаться: точная минута не гарантируется. Каждое окно продолжает сохранённый номер. После полуночи metadata официальных Artifacts выбирает прежнюю незавершённую дату, а не начинает новый номер. Просроченный checkpoint не заменяется пустым; опубликованные даты не переписываются и главная не откатывается на более старый выпуск.

Production использует расширяемый пул `config/candidates.json` (только публичные URL/category_hint/verification_urls), RSS и evergreen. Начальный пул содержит проверенные CI полные материалы; это **не заранее одобренные статьи**. Каждый проходит права, freshness для новостей, полноценность и независимые проверки. Другой источник выбирается при недостоверности, неполноте или неясных правах. Долговременная достаточность пула не гарантируется: общий повтор сюжета с архивом блокируется.

## Квота, сохранение и миграция

Лимиты24 HTTP/run,220/UTC-день и>=6сек сохранены, включая неуспешные запросы. Один mutex сериализует production и возможный исторический trial. 429/503, cooldown и Retry-After сохраняются; смена даты/версии не сбрасывает ledger. Дневная квота не гарантирует завершения12 статей: при её исчерпании следующий cron восстанавливает прогресс.

Закрытые источники/досье/черновики остаются только в защищённых Actions и AES-GCM checkpoint. Official download-artifact использует artifact ID и source run ID. Проверки метаданных/дешифровки/upload не обходятся. Checkpoint и ledger загружаются `always()` и хранятся90дней; не удалять их. Локально используются только вымышленные тестовые состояния.

Новый неопубликованный v31 checkpoint мигрирует в41: полный старый объект сохраняется в `legacy_v31`, `_quota_snapshot`, branch и preview переносятся. Старые approvals не считаются подтверждением новой политики. Уже написанные тексты не уничтожаются; для их использования необходимы полный источник/права/перепроверка. Существующий41 state и успешно принятые этапы продолжаются без перегенерации. `check`/`inspect` не вызывают Gemini. Не менять дату незавершённого номера и не обнулять счётчики.

## Права и редакционные отказы

Режим A — полный русский оригинал, B — полный перевод: только подтверждённые права именно на это использование, с атрибуцией/лицензией. C — самостоятельная русская статья из неохраняемых фактов: разрешение на факты не требуется, скрытый перевод/поверхностный рерайт запрещены. Собственные композиция, примеры, объяснения и формулировки проверяются отдельно. Обоснованный спор блокирует источник. Фото имеют отдельные grants/hash; отсутствие законного фото допустимо.

`config/rights.json` содержит только публичные доказательства и технические hashes. Закрытые договоры, переписку/контекст не помещать в публичный Git. Автоматически распознаётся узкий набор CC BY3/4/CC0; непонятное основание не разрешается ответом модели. Научные/медицинские/опасные факты требуют компетентных независимых подтверждений.

Адресный финальный отказ заменяет только явно указанные repair_ids. Общая композиционная проблема не удаляет случайную статью. Одинаковый отклонённый аудит повторно не вызывается; число вариантов ограничено. Безопасные коды и номера в журнале, подробности — только ciphertext. Блокировка не разрешает ослаблять gates.

## Первый запуск и наблюдение

После технически проверенного merge используйте автоматически начавшийся push-run main; **не создавайте второй параллельный запуск**. Если push не создал production, проверить Variables/права; при доступе штатный manual `phase=run,preview=false,target_date` пусто. Контроллер определяет ближайшую дату и восстанавливает существующий checkpoint. Не нужен отдельный trial/preview/Codespace.

Production preflight проверяет существующие Secrets без значений, policy4.1/12/06:00, обе Variables и читает metadata Pages. Непроверенная настройка Pages не мешает сохранять закрытый прогресс, но перед commit выпуск дополнительно требует **Pages Source=GitHub Actions** и cname387.su. Интеграция не подменяет отсутствие прав на настройки. Если необходимо, владелец открывает **Settings→Pages→Build and deployment→Source→GitHub Actions**, сохраняет существующий домен/HTTPS.

В журналах `[pipeline-status]` содержатся date,policy_version,article_target,готовые статьи,стадия,quota_day,requests_used_today,run_used,next_action,next_attempt. `PUBLISHED` подтверждается проверкой HTTPS, не зелёным checkpoint-job. Доставка имеет ограниченные попытки и монитор инцидентов. Обязательный финальный контроль — полный HTML каждой статьи, архив, главная, sitemap и отсутствие закрытых данных. Синтетический CI не считается настоящим номером.
