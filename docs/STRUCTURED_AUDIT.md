# Адресный аудит и продолжение выпуска 25 октября

> Актуальное описание ежедневного запуска: [DAILY_CONTROLLER.md](DAILY_CONTROLLER.md). Исторические шаги восстановления ниже не управляют новыми выпусками.

В прежнем `audit()` любой ValueError финального номера удалял статью с наименьшим отношением объёма к минимуму. В запусках №56 и №59 так были отправлены на переписывание статьи №1 и №5. Публичные журналы не сохраняли конкретную причину; они не доказывают наличие индивидуального дефекта этих статей.

Теперь финальная модель получает полные тексты и постоянные идентификаторы 1–8. Отказ содержит scope, code, affected article_ids, явно выбранные repair_ids, action, частную причину и конкретную инструкцию. Структура проверяется до применения. Произвольный общий ValueError, старый неструктурированный ответ и некорректные ID не запускают переписывание. В журнал попадают только коды, номера и фиксированные описания; причины, досье и оригиналы остаются в зашифрованном checkpoint.

Индивидуальная правка — один адресный запрос полной статьи с существующими доказательствами, затем прежние проверки объёма, содержательности и фактчекинг. Оригинал остаётся активным до успешной проверки замены. При 429/503/исчерпании квоты кандидат сохраняется для продолжения, повторное написание не требуется. Разнообразие и повторы исправляются только в явно указанных материалах; replace_story использует прежний ограниченный выбор проверенных альтернатив. Композицию можно исправить перестановкой без переписывания текстов. Неидентифицированная проблема блокирует выпуск, сохраняя все статьи.

Границы: максимум 6 завершённых аудитов, 4 раунда исправлений и 2 исправления одного сюжета. Неизменённый отклонённый номер не отправляется на аудит повторно. Ошибки транспорта и остановка по квоте не превращаются в редакционный отказ. Эти пределы сохраняются между запусками; редакционные пороги не ослаблены.

## Восстановление существующего выпуска

Последний checkpoint берётся штатным locate_checkpoint.py. Только внутри GitHub Actions на main ранее принятая статья, удалённая общим legacy-отказом, может быть восстановлена из checkpoint запуска №58 (run 40209759347, artifact 12605134114). Перед восстановлением проверяются дата, режим, ветка, план, источники, совпадение остальных семи статей, доказательств и отметки полного фактчекинга. Текущий счётчик запросов из последнего запуска сохраняется; старый счётчик не подменяет новый. Восстановление не означает одобрение: требуется новый структурированный аудит.

Фаза resume последовательно восстанавливает, исправляет только адресные замечания, проводит аудит и при успехе публикует с прежними шлюзами. Push проверенного исправления в main запускает это продолжение, если NEWS_RELEASE_APPROVED=true. До публикации даты 2026-10-25 обычные запланированные write/audit/publish также подхватывают этот незавершённый выпуск; отдельный cron не добавлен. После появления опубликованного issue.json маршрутизация возвращается к обычным датам. При исчерпании дневной квоты состояние сохраняется, следующий штатный запуск после смены дня UTC продолжает работу. Никакого ручного сброса ledger или повышения лимитов нет: 24 запроса за запуск, 220 в день, 6 секунд между запросами.

Расписание 06:00 МСК не изменено. Выпуск от 25 октября уже прошёл временной барьер; опубликован он будет только после успешного аудита. Закрытые артефакты и Secrets не переносятся из GitHub Actions. Локальные тесты используют вымышленные данные.
