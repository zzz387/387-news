# 387 News — установка автоматической редакции (первая проверяемая версия)

**Домен:** https://387.su  
**Репозиторий:** https://github.com/zzz387/387-news  
**Тариф:** GitHub Pages Free + Gemini API Free (без подключения платного биллинга).  
**Время выпуска:** не ранее 06:00 МСК, ежедневно; точная минута не гарантируется: у GitHub Actions бывают задержки очереди и публикации.

## Что содержится в архиве

Внутри только новые файлы, их надо **добавить к уже существующему сайту**, а не заменять сайт:

```text
.github/
  workflows/
    daily.yml
scripts/
  news.py
  test_news.py
```

Главная страница `index.html`, папка `archive/`, папка `issues/`, иллюстрации и файл `CNAME` **остаются**.

## Установка: 6 шагов

1. Распакуйте ZIP в пустую папку. Убедитесь, что там есть папки **`.github`** (с точкой в начале) и **`scripts`**.
2. Откройте **https://github.com/zzz387/387-news**, вкладку **Code**. Нажмите **Add file → Upload files**. Перетащите **обе папки** `.github` и `scripts` из распакованного архива на страницу. GitHub должен сохранить их пути как `.github/workflows/daily.yml`, `scripts/news.py`, `scripts/test_news.py`. Нажмите **Commit changes**. Если браузер не переносит скрытую папку `.github`, создайте файл вручную через **Add file → Create new file** с именем `.github/workflows/daily.yml`, вставив содержимое файла из архива; аналогично загрузите папку scripts.
3. В **Settings → Pages → Build and deployment → Source** поменяйте **Deploy from a branch** на **GitHub Actions**. Это ОБЯЗАТЕЛЬНО: коммиты от стандартного `GITHUB_TOKEN` не запускают Pages при старом режиме публикации. Домен `387.su` и Enforce HTTPS сохраните.
4. Убедитесь, что в **Settings → Secrets and variables → Actions** есть Repository secret **`GEMINI_API_KEY`**. Не раскрывайте ключ и не добавляйте платный биллинг.
5. Перейдите на вкладку **Actions** → слева **387 News — daily newspaper** → **Run workflow**. **Снимите/оставьте выключенным** флажок **Publish to 387.su now** → **Run workflow**. Это пробный запуск; сайт не должен измениться.
6. Откройте новый запуск во вкладке Actions и проверьте журнал шага **Research, write, validate and prepare newspaper**. При успехе будет `[approved] ...` и `DRY RUN`. Внизу запуска в разделе **Artifacts** появится архив `387-news-preview`: проверьте статьи и рубрики. Если красный крестик — смотрите причину ошибки; сайт останется прежним. После успешной проверки расписание начнёт работать автоматически.

## Расписание

GitHub Actions начинает исследование в 05:17 МСК (`17 2 * * *` UTC). После проверки текстов скрипт удерживает черновик **внутри задания**, не загружая его в публичный репозиторий до 06:00 МСК. Только потом (или позже, если обработка задержалась) отправляет готовые страницы на сайт. GitHub Pages также тратит время на доставку, поэтому обещать публикацию **ровно в 06:00** нельзя.

## Что умеет эта первая версия

- Берёт RSS и официальные страницы как проверяемую исходную информацию. **Не использует платный Google Search Grounding**, поскольку на текущем бесплатном тарифе для новых моделей он недоступен.
- Сначала составляет план, затем отдельно пишет статьи с источниками; делает дополнительную редакционную проверку.
- Требует 8 статей, 2 большие, все 3 обязательные рубрики, минимум 3500 слов в сумме, подтверждённые URL и корректную навигацию. Если проверка не пройдена, **не публикует ничего**, чтобы не заменять сайт слабым или некорректным материалом.
- Делает новый постоянный адрес `/issues/ГГГГ-ММ-ДД/`, сохраняет старые выпуски, обновляет главную страницу, архив и `sitemap.xml`.
- При повторной попытке за ту же дату не создаёт дубликат.
- Не меняет DNS, почту Gmail, ключи Cloudflare и старые страницы.

## Ограничения (важно)

- Автоматическая нейросетевая проверка **не равна профессиональному независимому фактчекингу**; недостоверные утверждения могут пройти. Для ответственного новостного издания полезна человеческая проверка перед публикацией.
- Источники могут быть недоступны, модель может вернуть ошибку или бесплатная квота Gemini может закончиться. Тогда **новый номер пропускается**, без расходов и без повреждения архива.
- Эта редакция публикует собственные иллюстрации из `assets`, а не новые фотографии. Для автоматической загрузки лицензированных фотографий потребуется отдельный механизм.
- В GitHub публичного репозитория видны статьи и код; ключ остаётся в Secrets.
- Если GitHub не позволяет записывать изменения, проверьте **Settings → Actions → General → Workflow permissions** и разрешите **Read and write permissions**. В workflow также задано `permissions: contents: write`.
- Если в вашем проекте Gemini модель `gemini-3.6-flash` недоступна в Free, в `.github/workflows/daily.yml` замените `GEMINI_MODEL` на `gemini-3.5-flash-lite` и повторите пробный запуск. Качество текста у Lite может быть ниже.
- Публикация через GitHub Actions требует сменить **Settings → Pages → Source на GitHub Actions**: иначе коммиты `GITHUB_TOKEN` сами по себе не обновят сайт.
